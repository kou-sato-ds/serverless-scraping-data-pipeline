# ADR-011: README の構造をテストで守る

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-09-11 |
| **関連 PR** | PR #17 (readme-structure) |
| **Ports** | 姉妹プロジェクト item 102 |

## 1. 背景

姉妹プロジェクトで、**45個の見出しが `> ` 付きで書かれていた**。
GitHub 上では引用ブロック内の文字列として灰色に沈み、
右側の目次には1つも載らない。1ヶ月以上気づかれなかった。

さらに索引テーブルに 4 列の行が混入していた——
それは **本リポジトリの ADR 索引から貼り間違えたもの** である。

## 2. 問題

同じ操作を両方のリポジトリで行っている以上、
こちらでも同種の事故が起きうる。そして：

| 事象 | 現在の検知手段 |
|---|---|
| 見出しが引用に沈む | 無し。エディタ上では違和感がない |
| ADR 索引テーブルの列数不一致 | 無し。Markdown はエラーを出さない |
| 索引行の重複 | 無し。差し替えが追記になっても気づかない |

**ADR-008 で「書いたものは辿れて初めて価値になる」と書いたが、
辿れる形で描画されなければ、書いたことにもならない。**

## 3. 決定

`tests/test_readme_structure.py` で以下を検証する。

| 検証 | 防ぐ事故 |
|---|---|
| 引用内に見出しが無いこと | 目次から消える |
| ADR 索引の列数が揃うこと | 表が崩れる |
| ADR 索引の行が連続すること | 間に別内容が挟まる |
| ADR 番号の重複が無いこと | 差し替えが追記になる |
| 姉妹リンクが残ること | 対称構造の導線が切れる |

### なぜ内容ではなく構造を検証するか

ADR-008 は「ADR が README から辿れるか」を検証している。
しかしそれは**文字列としての存在**を見ているだけであり、
その文字列が**見出しとして描画されるか**は見ていない。

テストが守っていたのは中身であって、見た目ではなかった。

## 4. 結果

### ポジティブ
- 見出しが引用に沈めば CI が赤くなる
- 索引テーブルの崩れを、読者が気づく前に検知できる

### ネガティブ / 残課題
- 検証できるのは構造であって、**表示の美しさではない**
- リンク先が実在するか（404 でないか）は未検証

## 5. 教訓

**書いた本人には正しく見える事故が、最も長く放置される。**

ADR-006 では「常に赤いチェックが赤信号の意味を破壊する」と書き、
ADR-010 では「エラーにならない異常が最も長く放置される」と書いた。

本件はその3例目である——エディタ上では違和感がなく、
CI は緑のまま、誰もプレビューを開かない。
**測っていないものは、壊れていても分からない。**
