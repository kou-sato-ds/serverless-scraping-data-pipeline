# ADR-018: 使われていない部品を数え、増やさない

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-13 |
| **関連 PR** | PR #27 (unwired-modules) |
| **Ratchet model** | 姉妹プロジェクト item 117 |

## 1. 背景

ADR-012〜017 で6つの部品を `src/` に追加し、それぞれテストで守った。

## 2. 問題

**テストが通っていても、`lambda_handler` から呼ばれていなければ本番では動いていない。**

| ADR | 部品 | 状態 |
|---|---|---|
| 012 | schema | 未接続 |
| 013 | backfill | 未接続(運用時に手動で使う想定) |
| 014 | incremental | 未接続 |
| 015 | jst_partitions | 未接続(読む側のヘルパー) |
| 016 | run_reconciliation | 未接続 |
| 017 | fetch_retry | 未接続 |

ADR-008 / ADR-009 で「書いたものが辿れること」「語れること」を守ってきたが、
**「動いていること」は誰も数えていなかった。**

## 3. 決定

`tests/test_unwired_modules.py` で、`app.py` から直接・間接に import されない部品を数える。

| ルール | 理由 |
|---|---|
| 未接続の部品は一覧に載せ、理由の ADR を書く | 黙って増やさない |
| 一覧に無い未接続の部品が現れたら赤 | 新しく作った部品を使わずに放置しない |
| 組み込んだのに一覧に残っていたら赤 | 一覧を実態に合わせ、縮む方向にしか動かさない |

### なぜ一度に全部組み込まないか

6つを同時に `lambda_handler` へ入れれば、どれが原因で壊れたか分からなくなる。
1本ずつ組み込み、一覧を1つずつ減らす。

## 4. 結果

### ポジティブ
- 「書いたが動いていない」部品の数が、いつでも分かる
- 部品を足すたびに「組み込むか、理由を書くか」の判断を強制できる

### ネガティブ / 残課題
- 呼ばれているかは import で判定する。import されていても実際には呼ばれていない関数までは見ない
- 一覧をゼロにするまでの組み込みは、後続 PR で1本ずつ行う

## 5. 教訓

**テストが守るのは「正しく作れたか」であって、「使われているか」ではない。**
