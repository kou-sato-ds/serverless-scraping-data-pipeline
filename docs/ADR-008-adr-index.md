# ADR-008: ADR 索引を README に置き、整合をテストで守る

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-08-22 |
| **関連 PR** | PR #14 (docs-index) |
| **Ports** | 姉妹プロジェクト item 90 (repository index) |

## 1. 背景

本リポジトリには ADR-001〜007 と PR #1〜#13 が積み上がっているが、
README がそれを案内していない。採用担当者が最初に開いた時、
**どの ADR から読めばよいかが分からない**。

## 2. 問題

ADR は書けば残るが、**辿れなければ存在しないのとほぼ同じ**である。

そして手書きの索引は必ず腐る。ADR を追加するたびに README を
更新する規律に頼れば、いずれ「README にあるが docs/ に無い」
または「docs/ にあるが README に無い」という乖離が生じる。

## 3. 決定

README 冒頭に ADR 索引を置き、**その整合を `tests/test_docs_index.py` で検証する**。

| 検証 | 内容 |
|---|---|
| STAGE 3 | 全 ADR が README から辿れること |
| STAGE 4 | README が参照する ADR が実在すること（逆方向） |
| STAGE 5 | 全 ADR が Status を宣言していること |
| STAGE 6 | 姉妹プロジェクトへのリンクが存在すること |

### なぜ双方向に検証するか

乖離は片側だけでは起きない。

- 索引にあるが実体が無い → 読者がリンクを辿って何も見つけられない
- 実体はあるが索引に無い → 書いた ADR の存在に気づかれない

**どちらも「エラーにならず、期待通りに機能しない」種類の劣化**であり、
テストでしか捕まえられない。

## 4. 結果

### ポジティブ
- ADR を追加して README を更新し忘れれば、CI が赤くなる
- 姉妹プロジェクトへの導線が構造的に維持される

### ネガティブ / 残課題
- 索引の**内容**（各 ADR の要約）は手書きのままであり、古くなりうる
- 検証できるのは「リンクの存在」であって「説明の正確さ」ではない

## 5. 教訓

**書いたものは、辿れて初めて価値になる。**

ADR-006 で「常に赤いチェックは赤信号の意味を破壊する」と書いたが、
同じ構造がドキュメントにもある——**案内されない文書が増えるほど、
リポジトリ全体の可読性は下がる**。量を増やすより、
入口を作る方が読者にとっての価値は大きい。
