# ADR-017: RSS 取得の再試行を、Lambda の残り時間の内側に収める

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-12 |
| **関連 PR** | PR #26 (fetch-retry-budget) |
| **Ports** | 姉妹プロジェクト item 116 |
| **Builds on** | ADR-003 (例外伝播 + DLQ) |

## 1. 背景

ADR-003 で「失敗したら例外を投げ、Lambda の非同期リトライと DLQ に任せる」と決めた。

## 2. 問題

| 事象 | ADR-003 だけの場合 |
|---|---|
| 一瞬のネットワーク不調 | 1分後まで再試行されない |
| 関数内で長く再試行しすぎる | タイムアウトで強制終了され、例外もログも残らず DLQ にも届かない |

## 3. 決定

`src/fetch_retry.py` で、関数内の短い再試行を加える。

| 原則 | 理由 |
|---|---|
| 一時的な失敗(タイムアウト・429・5xx)だけ再試行 | 原因不明の失敗を繰り返せば時間だけ失う |
| 指数バックオフ + フルジッター | 相手の回復を妨げず、再突撃を散らす |
| 締切は Lambda の残り時間から決める | 固定値ではタイムアウト設定の変更に追従できない |
| 安全余白5秒を残す | 例外を投げ、ログを書き、ADR-003 の経路へ渡すため |

### ADR-003 との関係

本 ADR は ADR-003 を置き換えない。**関数内で直せる短い不調だけを先に吸収し、
それ以外は今まで通り例外として ADR-003 に渡す。**
再試行が安全なのは、ADR-002 の冪等キーがあるからである。

## 4. 結果

### ポジティブ
- 一瞬の不調で1分待たずに済む
- 強制終了を避け、失敗は必ず例外として DLQ の経路に乗る

### ネガティブ / 残課題
- `lambda_handler` への組み込みは後続 PR
- 取得元のレート制限(Retry-After ヘッダ)の尊重は未実装

## 5. 教訓

**再試行の締切は、自分が使える残り時間から決める。**
締切を越えて粘れば、成功しても結果を返せず、失敗しても記録が残らない。
