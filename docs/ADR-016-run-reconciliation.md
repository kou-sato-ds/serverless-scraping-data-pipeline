# ADR-016: 取得した記事の行方を、1件残らず説明する

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-11 |
| **関連 PR** | PR #25 (run-reconciliation) |
| **Ports** | 姉妹プロジェクト item 115 |

## 1. 背景

1回の実行では、取得した記事が「書き込み」か「スキップ」のどちらかになる。
スキップには正当な理由がある(取得済み・ウォーターマーク外・中身が壊れている)。

## 2. 問題

**理由の無いまま消えた記事は、どこにも記録されない。**

| 事象 | 現在の挙動 |
|---|---|
| 書き込みもスキップもされない記事 | エラーにならず、ログにも出ない |
| 同じ記事の二重書き込み | ADR-002 のキーで同じ場所に収束し、気づけない |
| 想定外の理由でのスキップ | 理由が書いてあるので正常に見える |

## 3. 決定

`src/run_reconciliation.py` で実行ごとに収支を取る。

**取得件数 = 書き込み件数 + 理由付きスキップ件数**

許可するスキップ理由は3つに限定する(`already_stored` / `outside_watermark` / `invalid_payload`)。
それ以外の理由は、説明になっていないものとして報告する。

### なぜ収支が合っているときもログに出すか

無音では、合っていたのか確かめていないのか区別できない(ADR-010 と同じ判断)。

## 4. 結果

### ポジティブ
- 理由の無い消失を、件数と例(先頭5件)で報告できる
- Logs Insights で `filter run_balanced = 0` により不一致の実行を追える

### ネガティブ / 残課題
- `lambda_handler` への組み込みは後続 PR
- スキップ理由の追加は、許可リストの更新とセットで行う必要がある

## 5. 教訓

**「全部処理した」は、件数で示せて初めて言える。**
ADR-010 が「中身の異常」を、本 ADR は「行方の分からない記事」を扱う。
