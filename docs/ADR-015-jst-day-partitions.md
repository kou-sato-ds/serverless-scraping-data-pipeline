# ADR-015: 日本時間の1日は UTC パーティション2つにまたがる

| 項目 | 内容 |
|---|---|
| **Status** | Accepted |
| **Date** | 2026-10-10 |
| **関連 PR** | PR #24 (jst-day-partitions) |
| **Ports** | 姉妹プロジェクト item 119 |

## 1. 背景

S3 のパーティションは UTC の日付(`dt=YYYY-MM-DD`)で切られている。

## 2. 問題

日本時間 10/10 の1日は、UTC では 10/9 15:00 〜 10/10 15:00 である。

| 読み方 | 結果 |
|---|---|
| `dt=2026-10-10` だけ | 日本時間 0:00〜8:59 の記事が漏れる |
| 2パーティションを読むが時刻で切らない | 前後に余計な記事が混ざる |

どちらもエラーにならない。

## 3. 決定

**保存は UTC のまま変えず、読む側で計算する。**
`src/jst_partitions.py` の `read_plan()` が、読むべき2つのパーティションと UTC の正確な範囲を返す。

### なぜ保存側を日本時間に変えないか

既存のパーティションと形式が変われば、過去データの読み方が2通りになる。
過去を書き換えずに済む方を選んだ。

### なぜ固定オフセットか

日本には夏時間が無いため、+9:00 で正確に扱える。
Windows で zoneinfo を使うには tzdata パッケージが必要になるが、その依存を避けた。

## 4. 結果

### ポジティブ
- 「日本時間のある1日」を漏れなく、余計なく読める
- タイムゾーンの無い時刻を拒否し、9時間ずれの混入を防ぐ

### ネガティブ / 残課題
- 1日を読むのに2パーティション分のスキャンが必要(パーティションだけで絞るより約2倍)
- 夏時間のある地域の日付を扱うときは zoneinfo への切り替えが要る

## 5. 教訓

**保存の区切りと、読み手の区切りは一致しないことがある。**
一致しないとき、エラーは出ず、数字だけが静かにずれる。
